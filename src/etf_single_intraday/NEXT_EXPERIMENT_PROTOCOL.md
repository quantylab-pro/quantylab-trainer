# 수집 확장 이후 실험 우선순위

## 운영 데이터

운영 서버 mison048 `/home/quantylab/quantylab/var/etf_intraday/`:

- `snapshots/YYYYMMDD/시각/`: 26ETF 호가·체결강도, 평일 장중 매분.
- `context/YYYYMMDD/시각/nav_CODE.json`: NAV·괴리율·추적오차, 평일 09:00~15:25 5분 간격.
- 같은 폴더 `program_CODE.json`: 당일 프로그램 순매수. 빈 응답을 값 0으로 취급하지 않음.
- `context-health.json`: 파일 수, 빈 응답 수, 신선한 파일 수, 오류 여부.

일부 실시간 API는 날짜 없는 시각만 제공한다. `888888` 등 특수 행은 저장하되 학습 피처로 쓰지 않는다. 첫 페이지만 수집해 최신 상태를 보존하는 목적이며 전체 틱 이력이 아니다. 5분 간격 NAV를 120초 신선도 제한으로 결합하므로 모든 분봉을 채우지는 않는다. 기록 수를 늘리려고 과거 분봉으로 소급하거나 무제한 전방 채우기하지 않는다.

## 추가로 시도할 부분

1. **낮은 거래 수의 원인 분리**: 예측값 분포, 비용 초과 예측 비율, 실제 비용 초과 라벨 비율을 날짜/ETF별로 기록. 모델 수축과 실제 기회 부족을 구분한다. 최신 평가 결과를 보고 임계값을 낮추지 않는다.
2. **시장 요인과 고유 신호 분리**: 같은 분의 ETF 공통 움직임을 제외한 잔차를 예측하는 모델과 원수익 모델을 동일 날짜 분할로 비교. 특정 시장 급등 하루가 결과를 좌우하는 문제를 확인한다.
3. **사건 기반 진입**: 모든 분을 무작정 학습하는 대신, 그 시점까지 계산한 괴리율 확장/축소·스프레드 정상화·잔량 변화가 있는 시점만 선별. 미래 값으로 사건을 정의하지 않는다. 같은 대상 표본에서 기본 모델과 피처 추가 모델을 비교한다.
4. **체결 가능성과 수익 예측 분리**: 과도한 스프레드/낮은 잔량은 실행 필터로 처리하고, 수익 모델과 별도로 평가. 지정가 체결을 가정한 수익 증가는 주문 대기열/체결 데이터 없이는 인정하지 않는다.
5. **전일 문맥**: AI 분석 원문 자체보다 발표 시각이 확인된 전일 이벤트·시장 상태를 조건으로 추가. 현재 새 수집에 AI 재처리를 넣지는 않았다.

## 검증 규칙

- 최소 3일이면 날짜 분리 코드가 실행 가능할 뿐, 충분한 성능 증거는 아니다. 20거래일 축적 후 10일 학습/5일 검증/5일 잠금 평가를 첫 사전 계획으로 삼는다. 장기 일반화에는 더 많은 국면이 필요하다.
- 피처 제거 대비 비교, 추가 비용 스트레스, 진입 지연, 중복 진입 제한, 가장 좋은 날짜 제외 성과를 함께 보고한다.
- 거래 수·활성 날짜·유효 데이터 비율을 반드시 보고한다. 거래 0회를 수익 모델 성공으로 보지 않는다.
- 새 수집은 자동화했지만 자동 재학습/모델 승격/실주문은 활성화하지 않았다.
